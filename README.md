# ZK-ARCHE Comparative Authentication Evaluation

This repository is the comparative evaluation workspace for **ZK-ARCHE**, **EDHOC-over-TCP**, and **mTLS**. It contains the Rust protocol implementations used for comparative measurements, a separate C/libsodium ZK-ARCHE implementation for portability and cross-language validation, LAN benchmark tooling, Mininet experiments, physical-device resource measurement, and consolidated security testing.

## Implementations

### ZK-ARCHE v2 — Rust

The Rust ZK-ARCHE client/server under `src/bin/` implement:

- RPK setup with Schnorr proofs over Ristretto255;
- per-session `pid` values instead of sending the stable device identifier during AUTH;
- re-randomized role commitments;
- CDS/OR-style anonymous role-set membership proofs;
- ephemeral Ristretto Diffie-Hellman;
- HKDF-SHA256 session-key derivation;
- HMAC-based key confirmation;
- persistent replay protection; and
- parser/I/O hardening.

The former X25519 + ChaCha20-Poly1305 outer authentication tunnel is not part of the current v2 flow.

### EDHOC-over-TCP

`edhoc_client` and `edhoc_server` provide the constrained-authentication comparison baseline used by the benchmark harness.

### mTLS

`mtls_client` and `mtls_server` provide the certificate-based mutual-TLS comparison baseline. Local certificate material is generated by `scripts/gen_certs.sh` and benchmark setup tooling.

### ZK-ARCHE v2 — C/libsodium

`c_implementation/` contains a separate C implementation used for portability and cross-language evaluation.

It supports:

- full ZK-ARCHE v2 authentication;
- optional fast device-handle lookup; and
- device-only benchmark ablation mode.

The device-only mode intentionally removes the role-proof layer and should be treated as an ablation, not as the main ZK-ARCHE security configuration.

## One-time setup

```bash
python3 -m pip install -r requirements.txt
make setup
```

Build Rust binaries directly with:

```bash
make build
```

For the C implementation:

```bash
make c-deps
make c-build
```

## Local comparative benchmark

```bash
make bench
make plot
```

The benchmark harness writes raw data beneath `benchmarks/results/` and generates plotting/table artifacts from those results.

## Mininet experiments

Use Mininet for network effects such as latency, jitter, loss, bandwidth limits, and multi-client behavior. Mininet does **not** emulate Raspberry Pi CPU performance.

Example:

```bash
sudo env \
  "PATH=$HOME/.cargo/bin:$PATH" \
  "RUSTUP_HOME=$HOME/.rustup" \
  "CARGO_HOME=$HOME/.cargo" \
  .venv/bin/python experiments/mininet/mininet_tests_123.py \
  --project . \
  --protocol all \
  --test all \
  --clients 50 \
  --iterations 50 \
  --seed 42 \
  --network-model simple \
  --device-mix raspberry-pi \
  --background-traffic none
```

See `docs/MININET_EXPERIMENTS.md` for the experiment model and caveats.

## Physical hardware measurements

Use `experiments/hardware/hardware_resource_benchmark.py` on the physical device whose CPU, RAM, and power behavior you want to measure.

Example:

```bash
python3 experiments/hardware/hardware_resource_benchmark.py \
  --protocol zkarche \
  --role client \
  --device "Raspberry Pi 4" \
  --server "Core i7-6770HQ 2.60GHz" \
  --runs 50 \
  --cmd './target/release/zkarche_client --server 192.168.1.10:4000' \
  --power-mode fixed \
  --fixed-power-watts 3.2
```

See `docs/HARDWARE_BENCHMARKING.md` for measurement guidance.

## Security testing

Security tooling is consolidated under:

```text
experiments/security/security_test.py
```

Run the safe regression subset with:

```bash
make security-test
```

or:

```bash
make security-safe
```

This runs transcript, mutation, invalid-curve/parser, session, replay, and side-channel/RNG screening tests without fuzzing or DoS traffic.

Run individual categories with:

```bash
make security-transcript
make security-mutation
make security-invalid-curve
make security-session
make security-replay
make security-side-channel
```

Fuzzing:

```bash
cargo install cargo-fuzz
make security-fuzz
```

Authorized local DoS resilience tests:

```bash
make security-dos-zkarche
make security-dos-edhoc
make security-dos-mtls
```

`make security-all` invokes every category exposed by the consolidated runner, including fuzzing and DoS. Use it only when the required live server is prepared and those active tests are intended.

See `docs/SECURITY_TESTS.md` for exact runner behavior and evidence outputs.

## C implementation modes

### Full mode

```bash
make c-run-server
make c-setup-client
make c-run-client
```

### Fast lookup

```bash
make c-run-client-fast
```

This enables the device-handle lookup optimization.

### Device-only ablation

```bash
make c-run-server-bench
make c-run-client-device-only
```

This mode omits role re-randomization and role-set proofs to isolate their performance cost.

## Recommended evaluation methodology

1. Use physical devices for CPU, RAM, and measured power claims.
2. Use Mininet for network-behavior and multi-client experiments.
3. Use the same request/response semantics and iteration counts for protocol comparisons.
4. Separate full ZK-ARCHE results from fast-lookup optimization and device-only ablation results.
5. Preserve raw CSV/JSON/log evidence before generating figures or summary tables.
6. Clearly distinguish measured power from fixed-power energy estimates.

## Research scope

This repository supports comparative research and prototype evaluation. It is not a production authentication suite, and benchmark/security results should be interpreted within the exact implementation, hardware, network model, and test configuration used to generate them.
